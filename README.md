# Embedded Systems: CNN and SNN accelerators on PYNQ-Z2

Vivado and Vitis projects for two HLS accelerators on the PYNQ-Z2 (Zynq-7020):

| Folder | What it is |
| --- | --- |
| `cnn/class_7/` | Vivado project, CNN design (`class_7.xpr`, block design, `.xsa`) |
| `cnn/vitis_workspace/` | Vitis workspace: `hls_component` (CNN in HLS), `pynq_plat_clean` (platform), `ds_cnn_app` (ARM app) |
| `cnn/hls_src/` | HLS sources and weights for the CNN |
| `snn/class_8/` | Vivado project, SNN design (`class_8.xpr`, block design, `.xsa`) |
| `snn/vitis_workspace1/` | Vitis workspace: `snn_mlp_hls` (SNN in HLS), `platform`, `hello_world` (ARM app) |
| `snn/hls_src/` | HLS sources and weights for the SNN |

Only sources and settings are in git. Build output (`.runs`, `build/`, `export/`, HLS reports) is ignored and
is regenerated by the tools.

## Requirements

- **Vivado, Vitis and Vitis HLS 2026.1** (same version for all three)
- **PYNQ-Z2 board files** in Vivado: Tools -> Vivado Store -> Boards -> PYNQ-Z2
- PYNQ-Z2 board, micro-USB cable, boot jumper set to **JTAG**
- Linux: your user in the `dialout` group (`sudo usermod -aG dialout $USER`, then log out and in)
- Python environment: follow steps 1-4 of the course repos
  ([CNN](https://github.com/dbaniya/CNN_guest_lecture)); additionally `pip install pyserial albumentations h5py`

## How to open and build

1. **Vivado:** open `cnn/class_7/class_7.xpr` (or `snn/class_8/class_8.xpr`).
   The IP repository points to the HLS output in the Vitis workspace next to it (relative path).
   Generate Bitstream, then File -> Export -> Export Hardware (include bitstream) if you changed the design.
2. **Vitis:** File -> Open Workspace -> `cnn/vitis_workspace` (or `snn/vitis_workspace1`).
   Build the platform first, then the application.
   If you exported a new `.xsa`: platform -> Update Hardware Specification -> build.
3. **HLS** (only if you change the accelerator): in the HLS component run C Simulation -> C Synthesis -> Package.
4. **Run on the board:** Run the application. Zynq initialization uses **FSBL**.
   The debugger stops at `main()`: press **Continue (F5)**.

## Testing the CNN over UART

The ARM app waits for images over UART at **4,000,000 baud** (`UART_BAUD` in `helloworld.c`).
In the course script `send_images_uart.py` set `ROOT` (the `new_testing_data` folder), `SERIAL_PORT = "/dev/ttyUSB1"`
and `BAUD_RATE = 4000000`, then run `python send_images_uart.py`.

## Common problems

| Symptom | Fix |
| --- | --- |
| `invalid command name "ps7_init"` on Run | Use FSBL initialization. Never point ps7_init at `ds_cnn.tcl` (that is the HLS driver, not the init script) |
| Nothing on UART, Call Stack shows *PAUSED ON BREAKPOINT* in `main` | Press **Continue (F5)** |
| `Permission denied` on `/dev/ttyUSB1` | Add yourself to `dialout`, log out and in |
| `Device or resource busy` | Close `screen`/`picocom` (`fuser -v /dev/ttyUSB1`) |
| Garbage / no reply | `UART_BAUD` in C must equal `BAUD_RATE` in the script |
| Only `/dev/ttyUSB1` exists | Normal: `ttyUSB0` is taken by JTAG |
| Vivado: board part not found | Install PYNQ-Z2 board files (Vivado Store) |
| Vivado: CNN/SNN IP missing | Run Package in the HLS component, or check Settings -> IP -> Repository |
